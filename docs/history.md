# Project history

Mirr is an experiment in making a small, inspectable dependent-type and proof checker in TypeScript, inspired by Bend/BendTT. The numbered `hoas.*.ts` files are successive designs rather than a single linear application; they retain examples that should compile and counterexamples that should be rejected. The first three are preserved as commented-out sketches. This is a history of the ideas in those files, not a claim that every intermediate checker was sound.

1. **`hoas.1.ts` — the initial HOAS sketch.** Terms carry their types, while TypeScript functions represent binders (higher-order abstract syntax, or HOAS). Dependent tuples, choices, arrows, applications, constructors, and eliminators establish the basic vocabulary. A small evaluator reduces applications and case analysis; the checker and sample terms explore dependent fields and branches.
2. **`hoas.2.infer.ts` — simpler terms and inferred results.** Tuples/choices become `STRUCT`/`CHOICE`, with destructuring and matching as explicit operations. Function application and matching gain more result-type inference, and equality checking starts comparing dependent structures by opening their binders with fresh symbols. Examples test type families, constructors, and rejected mismatches.
3. **`hoas.3.equal.ts` — equality and recursion experiments.** The sketch adds explicit equality types/proofs and rewriting (`EQ`, `eq`, `RW`), plus experiments with recursive types and well-foundedness. These are exploratory built-in equality nodes, not the representation used in later versions.
4. **`hoas.4.bigStruct.ts` — a compiled surface language.** A parser/compiler replaces the hand-built test terms. A more compact core combines sums and dependent records as tagged ADTs with constructor signatures; it uses lambdas, multi-argument applications, dependent pattern matching, and `Type`/`Data` universes. The checker tests structural recursion and dependent branch refinement. Equality moves out of the core AST: `EQ` is expressed as substitution across predicates, with reflexivity initially supplied as an axiom. The growing example suite includes naturals, equality transport, and proofs about addition, alongside self-application and other consistency probes.
5. **`hoas.5.affinity.ts` — liveness and erasure.** Signatures mark arguments live or erased, and checking tracks uses of live symbols to reject duplication of non-`Data` values and use of erased values in live positions. It tightens universe/ADT formation, recursion and `sorry` checks, while expanding positive and negative tests for dependent matching, equality, arithmetic, and attempted paradoxes. This is the BendTT-like stage highlighted by the repository's README.
6. **`hoas.6.telescope.ts` — per-binder dependent signatures.** Function arguments, return types, and ADT fields are expressed as telescopes: each slot's type may depend on earlier slots. The code continues to refine liveness, dependent applications, match refinement, and lexicographic structural-recursion checks. Equality remains definable as predicate substitution; here `rfl` is written as an identity function rather than a special equality constructor. The surface compiler and proof/rejection examples continue to grow.
7. **`hoas.7.graph.ts` — the latest iteration.** The telescope core is carried forward with a more direct parser/elaborator that builds terms in a context rather than emitting TypeScript source for evaluation. It handles annotations, inferred lambda results, let bindings, constructors, applications, and dependent matches, while retaining the liveness and recursion checks. Its examples extend from basic types and naturals to commutativity/associativity of addition, multiplication laws, decidable equality, and tests rejecting invalid proofs and recursive definitions. The filename marks this iteration; it should not be read as a separate graph-based runtime architecture.

Across these iterations the direction is toward a minimal core with HOAS binders, ADTs and dependent elimination, definitional reduction, explicit resource restrictions, and proofs constructed in the surface language rather than privileged equality syntax. The files also document unresolved edges through their rejected examples and experimental code; the README lists compile-time arguments, mutual recursion, and macros as unsupported. Git history records incremental work on recursion, affinity, binder/telescope handling, parsing, and later arithmetic proofs, but the numbered files give the clearest overview of the design changes.
